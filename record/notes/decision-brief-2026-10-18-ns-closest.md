## What the code does

1. **Which texts select.** The primary set: each language's texts with no digit and, for CMN, YUE, JPN, KOR and THA, no Latin letter. The production command calls the lens without a subset (`entropy_phases.py`, the `LENS.run_files` call in `run`), and `run_files` defaults to `subset='primary'`.
2. **How texts weigh.** For each text, u = P / NS (the pipeline's syllable count over NS). An option's score is the median of |log u| over the language's selected texts, each text counting once. If any of its texts failed, the option is unavailable.
3. **The language's choice.** The production option with the smallest score. Calibration-only options (FIN-C) can't win. An exact tie goes to the first option in declared order, with no tolerance. If any production option is unavailable, the language has no choice (`closest` returns nothing rather than ranking the rest).
4. **How languages weigh.** The NS-closest universe takes each language's choice. Its calibration score is the plain mean of the languages' scores, each language counting once; with every combination allowed, that's the same as minimising the mean.
5. **Leave-one-text-out.** Diagnostic only. Each text is dropped in turn and the choice recomputed: per language, and across the universes with each text dropped from every language at once (`joint-text`). The results are reported and never change the selection.
6. **The all-texts set (secondary).** The production command doesn't run the lens on it. The lens command can (`--subset secondary`, with the fixed digit and letter readings), and it needs the anchored freeze before it will count read texts. So nothing is reselected on the secondary set, and its comparison with NS appears in the record only if that command is run separately.
7. **Reuse of NS.** The lens report says it's a diagnostic lens that keeps every universe. I found no line in the report step saying that NS chose the NS-closest universe and also sits in its rate's denominator (through SR).
